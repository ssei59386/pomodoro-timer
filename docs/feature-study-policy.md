# 勉強方針・後悔防止トリガー機能（設計メモ）

作成: 2026-07-08。ユーザーとの設計対話（数セッション）で固めた決定事項をまとめる。
CLAUDE.md 本体はポインタのみ、詳細はここに置く方針（`feedback_claude_md_lean`）。

## この機能が解決したい「本当の課題」

> 定期テストが全部終わったあとに「あの時期この単元に時間をかけすぎた。この時間を別の
> 科目に回せていればもっと点が取れたのに…」という後悔をなくす。

つまり本質は「**手遅れになってから気づく時間配分ミスを、その場で気づかせて選び直させる**」こと。
既存の「見通し」機能（`simulateForward` / `triageSubtopics`）は "間に合わなそう" を Dashboard に
黙って表示するだけ（気づくかは生徒任せ）だった。これを **能動的に問いかける** 形へ格上げする。

## 決定事項（再litigateしない）

### 1. 理解度の意味を「達成段階のハシゴ」に統一する

理解度は「どれくらいできる気がするか」という曖昧な連続値ではなく、**具体的な課題をどこまで
終えたか＝達成段階**として定義し直す。5段階（1〜5）で、既存の 0〜1 スケールに 0.2 刻みで対応
（理解度4 = 0.8 = 既存の DEFAULT_TARGET_UNDERSTANDING と一致）。

**数学・理科**

| 理解度 | 達成したこと | 次にやること |
|---|---|---|
| 1 | まだ手つかず | 教科書の公式・例題を理解する |
| 2 | 公式・例題を理解した | 教科書の基本練習問題を解く |
| 3 | 基本練習問題が完璧 | ワークの基本問題を解く |
| 4 | ワーク基本問題が解ける（**2回反復済み**・次章へOK） | 発展問題に挑戦 |
| 5 | 発展問題が解ける | 維持・応用 |

- 理解度3→4は「ワーク基本問題が2回反復して解ける」。4→5は「発展問題が解けるか」。
- 章内で複数の小項目を登録可能（数学でも）。
- 大前提: **数学・理科はどれだけ時間をかけてもいいから、各段階を完璧にしてから次の段階へ**
  進ませたい。ただし「段階を飛ばさない」は章と章の間の話ではなく、**1つの章の中でラダーを
  飛び級しない**という意味（3章が全部理解度1でも、それぞれ並行して少しずつ上げてよい）。
  この制約はラダーの達成条件そのものが担うので、特別な「ロック」機構は作らない。

**英語**（章あり教科）

- 英単語 = 理解度システムの外。既存の暗記システム（Leitner）にそのまま任せる。
- 文法と読解が**分かれている場合**は小項目（subtopic）で別トラックにする:
  - 読解: テスト範囲の長文をN等分。1長文を完璧に訳せるごとに1段階（例4長文なら1つ=理解度1…4つ=理解度4）
  - 文法: 範囲の教科書を半分理解=2、全部理解=3、章の文法問題が解ける=4（文法ワーク3回が基準）
- 分かれていない場合: 精読（全文訳せる）＋文法ワーク完了 = 理解度4。

**社会**

- ワーク周回数で理解度を決める: 1周=理解度2、2周=理解度3、3周=理解度4。
- **周回ベースに一本化**（現状の「暗記専用＝章なし・vocabのみ」を、章＋周回カウントに転換する）。

**国語**: 後回し（合意済み）。

### 2. 後悔防止トリガー（3日連続シグナル）

- アプリは毎日、既存の前向きシミュレーション（`simulateForward`）で各章/小項目が
  テストまでに終わる見込みかを裏で計算している。
- ある小項目/章が **3日連続で「間に合わない候補」（shortfallMinutes > 0）** に入り続けたら、
  Home で「続ける／切り替える」を問いかける。
  - 1日で聞かないのは「どれだけ時間をかけてもいい」前提と矛盾するから。3日粘っても
    改善しない時だけ声をかける（うるさすぎず、手遅れにもならない間隔）。
  - 「続ける」を選んだら数日（暫定3日）は再確認しない。
  - 「切り替える」を選んだらその項目は暗記モードへ（下記）。計画が組み替わる。
- 判断材料は既存のペース測定（`learnedProblemRates` / `subjectPaceMultiplier`）。新しい計測は作らない。

**「切り替える」を選んだ後の挙動（教科別）**

| 教科 | 切り替え先 |
|---|---|
| 数学・理科 | 深い理解を諦め「解き方を覚える」暗記モードへ |
| 英語 | 精読を諦め「訳文を暗記する」暗記モードへ |
| 社会 | 切替先はない。「もう十分」としてそれ以上の周回をやめ、次の章へ区切る |

将来的には暗記モード＝既存 Leitner 復習エンジンへの合流が理想（手離れが良い）。ただし v1 では
まず軽い `studyMode: 'memorize'` フラグ（後述）で表現し、フル合流は後続フェーズで検討。

### 3. 学習者への見せ方＝「勉強方針」画面

理解度の各段階が何を意味し、どうすれば上がるのかを、学習者にわかりやすく1画面にまとめる
（新画面 or セクション。ユーザーは新画面案を「一つの考え」として提示、柔軟に判断してよいと明言）。

## 実装フェーズ（このドキュメント時点の計画）

- **Phase 1（着手）**: 「勉強方針」画面を新設。教科ごとの理解度ラダー（各段階の意味・上げ方）と
  後悔防止トリガーの説明を1画面に集約。ラダー定義は単一の情報源（`src/data/studyPolicy.ts` 等）
  として持ち、他フェーズもここを参照。**純粋に追加のUI・データ**で既存ロジック無変更＝低リスク。
- **Phase 2**: 3日連続トリガー＋「続ける/切り替える」プロンプト（章を持つ教科=数学・理科・英語
  が対象。社会は Phase 3 の章化まで対象外）。`studyMode` フラグ（`'understand' | 'memorize'`、
  デフォルト understand）を Chapter / ChapterSubtopic に追加。切替時は暗記モード表示＋計画上の扱いを
  変える（理解度を無理に上げにいかず、shortfall 対象から外す）。連続 shortfall 日数のカウントは
  セッション履歴＋日付から導出 or 小さなカウンタを persist。
- **Phase 3（要・追加設計、未着手）**: 理解度の更新エンジン自体を達成段階ベースへ／社会の
  vocab→章化マイグレーション／英語の文法・読解トラック分割／暗記モードの Leitner フル合流。
  データモデル移行を伴い規模が大きいので、着手前に改めて設計・確認する。
